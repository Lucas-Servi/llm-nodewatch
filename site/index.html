Which node is burning your tokens?

nodewatch attaches to a LangGraph agent as a callback and reconstructs what each node actually cost — tokens, dollars, latency, and how many times it looped. It writes to one SQLite file. Nothing leaves your machine.

analyzer is 49% of the bill and it ran twice. A span tree would have made you work that out yourself.

pip install "llm-nodewatch[server]"

Two lines, no graph changes

import nodewatch

# these two lines are the integration
tracker = nodewatch.GraphTracker("my-graph")
result = await graph.ainvoke(
    state, config=tracker.config,
)

trace = tracker.finalize(query=q)
nodewatch.SQLiteStorage("runs.db").save(trace)

tracker.config is just {"callbacks": [tracker]}, so your graph is untouched. Node identity comes from LangGraph's own metadata, which is why the numbers land per node instead of per span.

Explore it from the CLI, a full-screen terminal dashboard, an MCP server your assistant can query, or a FastAPI router you mount in an app you already run.

Why not LangSmith, Langfuse or Phoenix?

Use those if you want a hosted UI, dataset management and team features. Use nodewatch when you want per-node cost accounting with nothing to operate.

Things that are easy to get wrong

Cache tokens. LangChain nests cache counts under usage_metadata["input_token_details"], and its input_tokens is inclusive of them. nodewatch subtracts them back out, so input stays exclusive and cached reads get priced at cache rates. Summing both double-counts your input.

Reasoning tokens. Providers already count reasoning inside output_tokens. Adding output_token_details.reasoning on top inflates cost on every thinking-enabled call, so nodewatch deliberately doesn't.

Worth checking in whichever tool you pick — both are silent when wrong.

Specification

Storage
One SQLite file, WAL mode. No daemon, no account, no collector.
Runtime dependencies
langchain-core, langgraph, typer, rich.
Captured per node
Input, output, thinking and cache tokens; cost; latency; loop count; tool calls.
Captured per call
Model, provider, stop reason, content-filter detection, and tool failures read from error payloads, not just raised exceptions.
Surfaces
CLI, terminal dashboard, MCP server (13 tools), mountable FastAPI router.
A/B runner
Cohorts keyed on the model that actually served each run, comparing only matched node paths.
Python
3.11 and up, tested through 3.14.
